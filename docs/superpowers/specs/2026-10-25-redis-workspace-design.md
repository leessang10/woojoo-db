# Redis 앱 구현 설계

작성일: 2026-10-25 · 상태: 구현 전 설계 초안

## 1. 방향과 전제

사용자 결정: Redis를 DB앱과 분리하고, 이후 사용성이 유사해지면 통합한다.

설계상 해석: 현재 Woojoo의 DB/AWS/API/Docker와 나란히 **Redis 작업 공간**을 추가한다. 별도 EXE나 새 저장소를 만들지 않는다. 이 해석은 제안이며, 사용자가 독립 실행 파일을 뜻했다면 배포 구조만 재설계한다.

목표는 접속 정보를 넣은 뒤 키의 구조, 값, 만료 상태, 큐 내용을 이해하기 쉽게 만드는 것이다. 첫 버전은 조회 중심으로 완결한다. 자료형과 업무 목적을 혼동하지 않는다. List를 자동으로 작업 큐라고 단정하거나 TTL만으로 캐시를 확정하지 않는다.

### 검토한 구조

| 방식 | 장점 | 비용 / 판단 |
| --- | --- | --- |
| DB 내부 Redis 엔진 | 기존 연결 UI 공유 | 사용자 결정에 따라 제외. SQL 모델에 종속되기 쉬움 |
| Woojoo 안의 독립 Redis 앱 | 공통 UI 재사용, 기능과 상태 독립, 향후 통합 용이 | 이번 설계 제안 |
| 독립 실행 파일과 저장소 | 배포와 제품 수명 주기 독립 | 설정·배포 중복. 현재 요구에는 우선 적용하지 않음 |

현재 근거: `src/App.tsx`의 `WorkArea`, `WORK_AREAS`, 앱별 컴포넌트와 `src-tauri/src/main.rs`의 모듈별 명령 등록. React/TypeScript, Tauri 2/Rust를 유지한다. 기존 미커밋 변경이 많으므로 구현할 때 공통 파일은 필요한 부분만 수정한다.

## 2. 첫 출시 범위

- Redis Standalone 단일 엔드포인트, 호스트/포트, 선택적 ACL 사용자명·비밀번호, TLS 인증서 검증, DB 번호 직접 지정.
- 연결 테스트, 프로필 저장/수정/삭제, 연결 전환, 명시적 재연결.
- 접두사 트리와 평면 키 목록, 패턴 검색, 자료형 필터, 키 직접 열기.
- String, Hash, List, Set, Sorted Set, Stream 조회.
- 캐시 보기: 사용자가 등록한 키 패턴을 대상으로 만료 현황과 값 조회.
- 큐 보기: 사용자가 등록한 List/Stream 키의 내용 및 이용 가능한 상태 조회.
- 한국어/영어, 다크/라이트, 키보드 탐색, 960×640 최소 크기.

후속 범위: 값 편집, TTL 변경, 선택 삭제, BullMQ 어댑터, Pub/Sub, RedisJSON, Cluster, Sentinel, SSH 터널, CLI 콘솔, 장기 모니터링. 1차에는 Redis 쓰기 명령을 노출하지 않는다. 프로필·즐겨찾기·보기 설정은 로컬 편집 가능하다.

지원 목표는 Redis 6.2 이상 Standalone이며 실제 검증 버전은 구현 시 고정한다. 모듈 자료형은 이름과 지원하지 않는다는 안내를 표시한다. Cluster 리다이렉션/MOVED는 지원 불가로 알리고 일부 노드 결과를 전체 데이터로 제시하지 않는다.

## 3. 사용자 흐름과 화면

앱 전환 메뉴의 Redis → 연결 추가 → 연결 테스트/연결 → 키 목록 → 키 선택 → 상세 조회.

- 상단: 연결 선택, 환경명, DB 번호, 연결 상태, 마지막 갱신 시각, 새로고침.
- 왼쪽: 연결과 접두사 트리, 저장한 캐시 패턴 및 큐 목록.
- 중앙 상단: **키 / 캐시 / 큐** 보기 전환, 검색, 자료형 필터.
- 중앙 목록: 키, 자료형, TTL, 항목 수 또는 길이. 크기 분석은 선택한 키에서 요청할 때만 수행.
- 상세 패널: 선택한 키의 전체 이름, 자료형별 값, 메타데이터, 갱신 시각. 좁은 창에서는 목록/상세 전환으로 공간 확보.

키 트리는 `:` 구분자를 기본값으로 사용하되 연결별 변경 가능하다. 이는 가상 폴더다. `user` 자체가 키인 동시에 `user:1`의 접두사여도 각각 접근 가능해야 한다. 구분자가 없는 키, 빈 구간, 비UTF-8 키도 손실 없이 취급한다.

키 목록에 실제 값을 미리 전부 넣지 않는다. 선택했을 때 상세를 조회한다. JSON은 전체 값이 유효하게 로드된 경우 펼쳐보기/원문을 제공하고, 잘린 값은 JSON 검증 실패로 오인하지 않게 표시한다. HTML은 렌더링하지 않고 텍스트로 표시한다.

### 자료형별 표현

| 자료형 | 화면 | 조회 전략 |
| --- | --- | --- |
| String | 텍스트 / JSON 트리 / Hex | STRLEN + 제한된 GETRANGE |
| Hash | 필드·값 표, 셀 상세 | HLEN + HSCAN |
| List | 원래 인덱스와 값 | LLEN + 제한된 LRANGE |
| Set | 멤버 목록 | SCARD + SSCAN |
| Sorted Set | 점수·멤버 표 | ZCARD + 제한된 ZRANGE WITHSCORES |
| Stream | ID·필드 값, 그룹/소비자 탭 | XLEN + XRANGE/XREVRANGE, XINFO, XPENDING |

Hash/Set은 커서로 더 불러온다. List/Sorted Set은 범위 이동, Stream은 ID 기준 이동을 사용한다. 공통 UI에 페이지 번호를 억지로 강제하지 않는다. List가 변경되면 인덱스 이동으로 항목이 중복/누락될 수 있어 실시간 스냅샷이 아님을 표시한다. Stream ID는 문자열로, 큰 정수는 10진 문자열로 전달하여 JS 정밀도 손실을 피한다.

## 4. 캐시 보기

사용자가 `cache:*`, `session:*` 같은 패턴을 등록한다. 특정 패턴과 무관한 전체 키에도 만료 상태 필터를 적용할 수 있다.

- TTL 상태: 만료 없음 / 1분 이내 / 1~5분 / 5~60분 / 1시간 이상 / 조회 중 사라짐 / 권한 부족.
- 구간별 막대와 키 목록을 연동한다. 차트 선택은 해당 구간의 탐색된 키만 필터링한다.
- 항상 `탐색한 2,400개 기준 · 탐색 진행 중 · 마지막 조회 14:32:10`처럼 범위와 시각을 표시한다. 무작위 표본이 아니므로 전체 비율로 추정하지 않는다.
- 만료 카운트다운은 마지막 관측 TTL을 바탕으로 표시하며, 0이 되면 재조회 전에는 ‘만료 예상’이다.
- 서버 INFO의 hit/miss를 지원하면 서버 누적 지표로만 별도 표시한다. 키별·패턴별·선택 DB별 적중률로 표현하지 않는다. 허용되지 않으면 해당 영역만 미지원 처리한다.

## 5. 큐 보기

큐 등록 시 표시 이름, 정확한 키, 종류(List/Stream), List의 처리 방향(알 수 없음/왼쪽/오른쪽)을 저장한다. 후보를 발견해도 사용자가 큐로 지정해야 목적 보기로 노출한다.

**List:** 길이, 인덱스, 내용 미리보기. 처리 방향이 없으면 좌/우 끝으로만 표시한다. 길이를 처리 대기 작업 수로 확정하지 않고, 처리 중·성공·실패는 알 수 없음으로 남긴다.

**Stream:** 메시지 목록, 그룹별 pending, 소비자별 pending/idle, 서버가 제공하는 경우에만 lag. Pending은 그룹에 전달됐지만 ACK되지 않은 메시지이며 실패 개수가 아니다. 서로 다른 그룹의 pending을 고유 작업 수로 합산하지 않는다. 그룹이 없는 Stream도 조회 가능하다.

조회에는 POP, XREADGROUP, XACK, CLAIM 계열을 사용하지 않는다. 사용자 메시지를 소비하거나 소비 상태를 변경하지 않는다. BullMQ 작업 상태와 재시도는 이후 전용 어댑터를 통해 지원하며, 내부 키를 임의 수정하는 방식은 채택하지 않는다.

## 6. 탐색·성능·정확성

KEYS 대신 SCAN을 사용한다. Redis SCAN은 중복과 빈 배치를 반환할 수 있고 COUNT는 결과 상한이 아니다. 커서 0만 완료로 처리한다. 클라이언트가 원본 키 바이트로 중복 제거하며, 순회 완료도 특정 시점의 스냅샷을 보장하지 않는다.

초기 제안 기본값(검증 후 조정 가능):

- SCAN COUNT 200, 화면 메타데이터는 최대 50키씩 파이프라인 처리.
- 한 번의 더 불러오기 작업에 최대 10회 SCAN 또는 1초 예산. 부족하면 부분 결과와 다음 커서를 반환한다.
- 키 인덱스 보관: 최대 10,000키 또는 32MiB. 도달 시 일시 중단하고 검색 범위를 좁히도록 안내. 숨겨진 무제한 누적 금지.
- 상세 항목 기본 100개, 화면 값 미리보기 64KiB, IPC 응답 상한 2MiB.
- 연결 시간 제한 5초, 조회 10초. 취소는 후속 작업 중단과 응답 폐기로 구현하며 이미 보낸 Redis 명령의 서버 실행 취소를 보장하지 않는다.
- 자동 갱신 기본 꺼짐. 켜면 활성 상세/등록 큐만 5초 간격, 겹치는 요청 금지. 숨겨진 작업 공간과 연결 해제 시 타이머 중단. 전체 SCAN을 주기적으로 반복하지 않는다.

주의: HSCAN/SSCAN의 COUNT, LRANGE의 항목 수 제한은 응답 바이트 상한이 아니다. 거대 필드/멤버에 대비해 transport/parser의 수신 예산을 별도 구현한다. 제한 초과 시 해당 읽기 연결을 폐기하고 ‘항목이 너무 커 미리보기를 중단함’으로 반환한다. 드라이버에 수신 상한 제어가 없다면 제한 가능한 읽기 계층을 검증한 뒤 출시한다. IPC에서 잘라내는 것만으로 메모리 안전을 보장한다고 주장하지 않는다.

정렬·접두사별 개수·TTL 분포는 탐색한 결과 범위에만 적용한다. 서버 DB 전체 키 수(DBSIZE 사용 가능 시)와 현재 탐색 수를 별도로 표시한다. ‘검색 결과 없음’은 순회 완료 후에만 사용하고, 예산 중단은 ‘아직 발견하지 못함’이다.

키 만료, 삭제, 자료형 변경은 항목 단위 상태로 처리한다. TYPE/PTTL/값 조회 사이의 변화도 정상적인 경쟁 상태다. 권한 부족과 만료를 동일하게 표시하지 않는다.

## 7. 모듈 경계

```text
src/redis/
  RedisWorkspace.tsx        앱 조합 및 호스트 연결
  ConnectionDialog.tsx      Redis 전용 연결 폼
  KeyExplorer.tsx           트리·키 목록
  KeyDetail.tsx             자료형별 뷰어 선택
  viewers/                 String/Hash/List/Set/ZSet/Stream
  CacheView.tsx             만료 분포와 패턴
  QueueView.tsx             List/Stream 목적 보기
  api.ts                   타입 지정 IPC
  model.ts                 Redis 독립 자료형
  state.ts                 연결·선택·조회 상태
  redis.css                앱 전용 스타일

src-tauri/src/redis/
  mod.rs                   Tauri 명령
  connection.rs            세션·TLS·기능 확인
  explorer.rs              키 탐색 및 메타데이터
  values.rs                자료형별 제한 조회
  queues.rs                조회 전용 큐 어댑터
  store.rs                 프로필·보기·즐겨찾기 저장
  types.rs                 IPC DTO
```

Rust Redis 드라이버 후보는 redis-rs의 async/Tokio 및 TLS 기능이다. 정확한 버전/기능 플래그는 구현 시 호환성 검증 후 lockfile에 고정한다. SQLx 세션과 Redis 세션은 분리한다.

재사용: 기존 공통 UI 컴포넌트, 테마·언어 컨텍스트, 확인 대화상자, 자격증명 저장의 네이티브 구현. Redis 모델은 DB의 Profile/Table/Result와 SQL 탭 모델을 import하지 않는다. 거대한 App.tsx에 Redis 상태를 추가하지 않는다.

호스트 인터페이스는 활성 여부와 공통 표시 설정에 한정한다. 나중에 DB 앱으로 통합할 때 RedisWorkspace를 호스팅하는 위치를 바꾸고, 연결 선택 UI만 조정할 수 있도록 한다. 지금 범용 플러그인 프레임워크를 신설하지 않는다.

### IPC 계약

- `redis_connect`, `redis_test_connection`, `redis_disconnect`
- `redis_profiles_load/save/delete`, `redis_views_load/save/delete`
- `redis_scan`, `redis_key_metadata`, `redis_read_value`
- `redis_queue_inspect`, `redis_server_info`, `redis_cancel`

모든 조회는 sessionId, requestId, generation을 갖는다. 세션은 profileId+DB 번호에 고정하고, 동시에 공유하는 소켓의 SELECT를 화면마다 바꾸지 않는다. 연결/DB/검색을 바꾸면 generation을 올려 늦게 도착한 결과를 폐기한다. 커서는 문자열/불투명 토큰으로 전달하고 세션·검색 조건에 묶는다.

응답에는 observedAt, partial/truncated, nextCursor와 지원 여부를 담는다. 오류는 AUTH_FAILED, TLS_FAILED, FORBIDDEN, TIMEOUT, DISCONNECTED, KEY_MISSING, TYPE_CHANGED, UNSUPPORTED, TOO_LARGE로 구분한다. 서버 원문 오류는 비밀번호/URI를 제거한 후 상세에 표시한다.

키와 바이너리 값은 base64 원본과 별도 표시용 문자열을 갖는다. 인코딩 후 생기는 문자열을 키의 ID로 사용하지 않는다. PTTL -1과 -2는 숫자를 그대로 UI에 흘리지 않고 no-expiry/missing 상태로 변환한다.

## 8. 연결·저장·수명 주기

- 연결 프로필은 비밀을 제외하고 앱 데이터 영역의 버전 지정 Redis 전용 파일에 원자적으로 저장한다. 저장한 보기와 즐겨찾기는 profileId+DB 번호로 구분한다.
- 비밀번호는 연결 요청 후 프론트 상태에서 제거하고 Rust 메모리에 보관. 사용자가 ‘기억’을 선택한 경우에만 Windows 자격증명 저장소 사용.
- 기존 `credentials.rs`의 `Woojoo/Database/{id}`는 Redis와 공유하지 않는다. namespace 매개변수를 도입하되 기존 DB 대상 문자열은 그대로 유지하고 Redis는 `Woojoo/Redis/{id}`를 사용한다. 다른 OS에서 영구 저장을 지원하지 않으면 기억 옵션을 비활성화한다.
- 비밀 저장 식별 정보는 호스트·포트·사용자·DB·TLS 설정과 묶고, 변경 시 기존 비밀을 자동 재사용하지 않는다.
- TLS 기본은 서버 인증서/호스트 검증. 사용자 CA/mTLS UI는 후속 범위. TLS 실패를 평문 재연결로 우회하지 않는다.
- 재시작 시 프로필/선택한 보기만 복원. 키 값·큐 payload·조회 결과는 디스크나 로그에 자동 저장하지 않는다. 최초 버전은 자동 재접속하지 않는다.
- 연결 종료/프로필 삭제/앱 종료 시 세션과 진행 작업을 해제한다. 숨겨진 앱의 네트워크 갱신은 멈추되 사용자가 돌아오면 기존 표시와 마지막 조회 시각을 유지한다.
- INFO, DBSIZE, XINFO 등 개별 명령이 ACL로 거절되어도 사용할 수 있는 키 조회는 유지한다. 허용된 읽기 명령을 백엔드에서 열거하고 임의 명령 실행 IPC는 만들지 않는다.
- 브라우저 개발 화면은 명시적 데모 fixture만 지원. 실제 접속은 Tauri Rust에서 수행한다.

## 9. 구현 순서와 완료 기준

1. **앱과 연결**: 앱 메뉴, 빈 상태, 프로필, 비밀 저장 분리, 실제 Redis 연결/해제, TLS/인증 오류.
2. **키 탐색과 값**: SCAN, 키 트리, 자료형 6종, 페이지/커서, 바이너리, 크기 제한, 비동기 응답 격리.
3. **캐시**: 패턴 등록, TTL 구간, 관측 시각, 부분 집계, 클릭 필터.
4. **큐**: List 방향 설정, Stream 그룹·pending·소비자, 관측 전용 갱신.
5. **출시 검증**: 실제 서버·제한 ACL·거대 값·대량 키, 기존 앱 전환 회귀 및 데스크톱 빌드.

단계 1~4가 첫 출시 범위다. 값 편집/삭제를 섞어 범위를 늘리지 않는다.

핵심 검증:

- Vitest: 접두사 충돌, 키 바이트 동일성, TTL 상태, SCAN 중복/빈 배치/종료, 큰 정수, 검색 generation과 부분 통계.
- Rust 통합: 각 자료형, 인증/TLS 실패, ACL 부분 허용, TTL/삭제/타입 변경 경쟁, 거대 응답 중단, DB별 세션 격리, 시간 제한과 종료.
- UI: 연결 저장/전환, 키 직접 열기, 더 불러오기/취소, 검색 중 연결 변경, 캐시 구간 이동, List/Stream 조회, 양 테마/언어.
- 부작용 검증: 큐 조회 전후 List 길이·내용, 그룹 pending 및 전달 상태가 조회에 의해 변경되지 않는지 별도 fixture에서 검증.
- 성능 fixture: 10만 키에서도 전체 선로딩 없이 첫 배치 표시. UI 반응 목표 100ms 이내, 로컬 fixture 최초 목록 목표 2초 이내는 측정 목표이며 실서버 SLA로 약속하지 않는다.
- 수신 예산 초과 테스트는 많은 작은 항목과 하나의 거대 항목을 모두 포함한다.
- 기존 Vitest/Playwright/Rust 검사와 Tauri 빌드 중 변경 범위에 맞는 검사 실행. 검증 버전과 실행 결과를 구현 완료 보고에 기록한다.
