# Woojoo v0.1.4

데이터베이스, AWS, HTTP API를 한 앱에서 다루는 백엔드 작업 공간으로 확장했습니다.

## 주요 변경

### AWS 작업 영역

- 왼쪽 레일에서 데이터베이스와 AWS 작업 영역을 전환합니다. 데이터베이스의 열린 탭과 작업 상태를 유지합니다.
- 로컬 AWS CLI의 프로필과 리전을 선택하고 EC2, RDS, S3, CloudWatch Logs의 리소스 목록과 상세 정보를 확인합니다.
- S3 폴더·객체와 CloudWatch 로그 이벤트를 탐색하고, 인프라 맵에서 VPC·서브넷·리소스 관계를 확인합니다.
- RDS 상세 화면에서 기존 데이터베이스 연결 화면으로 이어집니다.
- AWS 변경 작업은 기본적으로 비활성화됩니다. 설정에서 허용한 뒤에도 실행 명령 검토와 대상 리소스 이름 확인을 거칩니다.

### API 작업 영역

- HTTP 요청을 여러 탭에서 작성하고 전송하는 로컬 API 클라이언트를 추가했습니다.
- 쿼리 파라미터, 헤더, 요청 본문, 인증, 환경 변수를 설정하고 응답 상태·헤더·본문을 확인합니다.
- 요청과 컬렉션, 환경, 실행 기록을 로컬 SQLite에 저장합니다.
- cURL 가져오기와 복사, 요청 취소, 제한 시간과 TLS 검증 설정을 지원합니다.

### 설정과 화면 구성

- 설정에서 테마, 쿼리 결과 행 제한, SQL 편집기 글자 크기를 변경합니다.
- AWS 변경 작업 허용 여부와 운영 프로필 판별 단어를 설정합니다.
- 쿼리 기록을 오른쪽 패널로 옮겨 SQL과 나란히 확인할 수 있습니다. 전체 기록은 별도 탭에서 탐색합니다.
- `Ctrl+Alt+B`로 쿼리 기록 패널을 열고 닫습니다.
- 사이드바 상단의 브랜드와 제목을 정리해 탐색 공간을 넓혔습니다.

## 다운로드

- `Woojoo-0.1.4-windows-x64.exe`: 설치 없이 실행하는 Windows x64 앱. Microsoft WebView2 런타임이 필요합니다.
- `SHA256SUMS.txt`: 실행 파일의 SHA-256 체크섬.
- 기존 앱을 종료한 뒤 새 EXE로 실행하세요. 실행 파일은 코드 서명되어 있지 않습니다.
- AWS 기능에는 인증된 로컬 AWS CLI와 해당 리소스에 대한 권한이 필요합니다.

## 검증

- 프런트엔드 단위 테스트 51개와 TypeScript/Vite 빌드 통과.
- Rust 테스트 43개 통과. 별도 DB·AWS 환경이 필요한 통합 테스트 5개 제외.
- UI 테스트 94개 중 92개 통과(실패 항목 재검증 포함). `structure.spec.ts`의 DB 인코딩·MySQL charset 표시 검사 2개는 v0.1.3 릴리즈에서도 기록된 동일 실패가 남아 있습니다.
- Windows x64 최적화 빌드와 배포 EXE 검사 통과. 개발 서버 없이 SQLite 연결·테이블 생성·탭 이름 변경·순서 변경·닫기·연결 전환, 로컬 HTTP 서버에 대한 실제 API 요청과 JSON 응답 표시를 확인했습니다.
- 실제 AWS 계정에 대한 변경 작업과 외부 PostgreSQL·MySQL·MariaDB 서버는 이번 릴리즈에서 검증하지 않았습니다.
