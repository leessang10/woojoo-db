## 범위와 방법

현재 소스를 로컬 Vite로 실행하고 Codex 내장 브라우저의 실제 화면과 접근성 트리를 점검했다. 1280×720, 한국어, 다크 테마 중심이며 라이트 테마도 비교했다. 이번 실행에서 직접 캡처한 17개 화면을 근거로 한다. 데이터 흐름은 기존 테스트 fixture로 확인했다. 앱 소스는 수정하지 않았다.

목표: 연결 설정 → 탐색 → SQL 실행 → 결과 확인/편집 → 구조/ERD → 기록·설정의 사용 마찰을 찾는다.

## 유지할 장점

- SQL 툴바의 한 줄 구성과 그룹 구분, 오른쪽 실행 버튼.
- 연결·스키마 경로와 데이터/구조/ERD 탭 분리.
- 셀 편집의 대기열 표현과 취소 시 포커스 복귀.
- SQL 템플릿의 검색·설명과 실행 전 검토 안내.
- 다크/라이트 테마의 일관된 주요 화면 구조.

## 접근성 관찰

SQL 열기 버튼의 DOM 측정 결과는 높이 21px, 너비 약 55.5px, 글자 10.5px였다. 밀도는 높지만 반복 클릭과 작은 글자 읽기에 부담이 될 수 있다. Tab 키로 다음 다운로드 버튼에 이동함을 확인했다. 연결 입력에는 레이블, 셀 편집에는 입력 포커스, 오류에는 alert 의미가 있었다. 스크린리더 실사용, 전체 키보드 순회, 색 대비 전수 측정, 확대 배율별 리플로우는 검증하지 않았으며 WCAG 준수 판정을 내리지 않는다.

## 검증 한계

Windows 네이티브 창, 실제 RDS 인증/TLS, 자격 증명 저장·복원, 실행 내역 백엔드, COMMIT/ROLLBACK, 파일 선택/가져오기, 대규모 데이터·다중 관계 ERD, 다중 모니터 DPI 및 영문 레이아웃은 이번에 재검증하지 않았다. 이전 테스트 성공 여부를 이번 감사의 증거로 사용하지 않았다. 브라우저 제한에서 발견한 문제는 네이티브 앱 문제로 일반화하지 않는다.

### 2. 연결 폼 — 개선 필요

엔진과 TLS, 자격 증명 옵션의 의미는 명확하다. 1280×720에서 하단 그룹·환경·주요 버튼이 처음 화면 밖으로 밀린다. 연결 버튼 영역을 고정하고 선택 항목을 접는 방식을 권장한다.

![2. 연결 폼](C:/Users/codecrain/projects/woojoo-db/docs/research/ui-audit-2026-10-21/02-connection.png)

### 3. 연결 오류 — 개선 필요 / 브라우저 한정

브라우저에서 연결 불가를 안내하면서 연결하기/연결 테스트는 활성 상태다. 연결하기를 누르면 같은 제한을 오류로 반복한다. 실제 네트워크·인증 실패 화면은 이번에 검증하지 않았다.

![3. 연결 오류](C:/Users/codecrain/projects/woojoo-db/docs/research/ui-audit-2026-10-21/03-connection-error.png)

### 4. 탐색·SQL 작업 공간 — 양호 / 공간 개선

한 줄 툴바, 활성 탭, 연결·스키마 경로가 명확하다. SQL 세 줄이어도 편집 영역 높이가 고정되어 결과 영역이 줄어든다. 편집기/결과 사이 크기 조절이나 접기 기능이 유용하다.

![4. 탐색·SQL 작업 공간](C:/Users/codecrain/projects/woojoo-db/docs/research/ui-audit-2026-10-21/04-workspace.png)

### 5. 셀 편집 — 양호

편집 대상 테이블·컬럼·행을 표시하고 “변경 대기열에 추가”로 즉시 반영이 아님을 알린다. 입력 포커스와 취소 후 원래 셀 복귀를 확인했다. 실제 DB 반영은 수행하지 않았다.

![5. 셀 편집](C:/Users/codecrain/projects/woojoo-db/docs/research/ui-audit-2026-10-21/05-cell-edit.png)

요약, 객체 종류 탭, 검색, 테이블별 작업의 위계가 명확하다. 데이터 보기와 구조 보기로 이동하기 쉽다. 많은 테이블을 가진 목록은 검증하지 않았다.

캔버스 조작, 속성, 내보내기를 구분한다. “이 기기에 자동 저장”과 “커밋”이 공존하므로 로컬 배치 저장과 DB 변경 적용의 차이를 더 분명히 할 여지가 있다. 한 테이블·관계 없음 상태만 검증했다.

테마·언어·사이드바 설정을 간결하게 제공한다. 글자 크기나 화면 밀도 설정은 보이지 않는다. 작은 기본 글자를 보완할 사용자 옵션을 권장한다.

브라우저에서는 데스크톱 전용 안내가 나타난다. 실제 실행 목록과 취소/상세 흐름은 이 환경에서 검증 불가. “저장된 기록”과 별도 메뉴로 존재해 사용자에게 범위 차이를 안내할 필요가 있다.

### 12. SQL 실행 성공 — 양호

SELECT * FROM users LIMIT 2; 실행 후 두 행과 시간이 표시되었다. 실행 중 비활성 처리와 로딩 안내를 확인했다. 데이터는 데모다.

![12. SQL 실행 성공](C:/Users/codecrain/projects/woojoo-db/docs/research/ui-audit-2026-10-21/12-query-result.png)

### 13. 기록 재사용 — 개선 여지

검색·불러오기와 SQL 값 저장 안내가 있다. 결과의 12ms와 기록의 365ms가 다른데 시간의 측정 범위가 설명되지 않는다. “DB 처리 시간”과 “전체 소요 시간”을 구별하거나 측정 기준을 통일할 것을 권장한다.

![13. 기록 재사용](C:/Users/codecrain/projects/woojoo-db/docs/research/ui-audit-2026-10-21/13-history.png)

### 14. SQL 실행 실패 — 우선 개선

성공한 쿼리 뒤 BROKEN;을 실행하면 오류 배너가 뜨지만 이전 두 행, 초록 체크, 12ms는 유지된다. “이전 성공 결과” 표시 없이 현재 SQL 결과로 오해할 수 있다. 오류 상태와 이전 결과를 명확히 구분해야 한다.

![14. SQL 실행 실패](C:/Users/codecrain/projects/woojoo-db/docs/research/ui-audit-2026-10-21/14-query-error.png)
